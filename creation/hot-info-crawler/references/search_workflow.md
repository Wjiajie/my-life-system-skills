# 检索执行流程

本文档定义从配置读取到最终合并的可移植流程。浏览器和网页工具由当前宿主决定，不依赖固定 skill 名称。

## 1. 初始化与断点

1. 读取 `config.json` 和 `user_config.md`。
2. 打开当天报告，扫描 `<!-- section:*_done -->`。
3. 已完成的板块不重复抓取；存在 `section:all_done` 时先询问是否重跑。
4. 中间分块与日志写到系统临时目录，文件名包含日期与主题 ID。

## 2. 平台与工具选择

按主题的 `优先平台` 与全局开关的交集执行。

| 来源 | 首选访问方式 | 失败处理 |
|---|---|---|
| AI HOT API / Feed JSON | 直接 HTTP/API | 记录状态码或不可达原因，不用搜索结果伪装 API 数据 |
| HuggingFace Papers | 公开网页或 web 工具 | 回退到论文原始页或官方索引 |
| X.com / Reddit / 即刻 | 有登录态的宿主浏览器 | 登录或反爬失败时，只用可访问的公开原始页；不足则标记限制 |
| YouTube | 页面 + captions/transcript | 字幕不可用时只保留验证过的元数据与简介信息 |
| 官方博客 / 公告 | 原始页面 | 搜索引擎只用于发现，报告链接必须指向原始页 |

需要登录态时，在 Codex 可优先使用 `chrome:control-chrome`；独立交互浏览可用 `browser:control-in-app-browser`；公开检索与核验可用内置 web 工具。是否可用以当前会话实际暴露的能力为准。

## 3. Feed

对每个启用的 Feed：

1. 读取 JSON URL，校验返回格式与日期。
2. 仅保留当前时间窗口内的条目。
3. 使用 canonical URL 去重；没有 canonical URL 时再用规范化标题去重。
4. 提取标题、原始链接、发布时间、可见互动数据和正文/节目描述。
5. 英文自然语言内容先翻译为中文，再按质量规则筛选。

详细字段与输出格式见 `follow_builders_feed.md`。

## 4. 主题检索

### AI 工具 / agent

严格按 `aihot_skill.md` 调用 AI HOT API。不要先抓 X.com、HuggingFace、YouTube 或 Reddit 来替代 API 结果。API 不可用时要报告该来源失败。

### LLM 理论

读取 HuggingFace Papers 日期页或搜索页，必要时打开论文原始页核对标题、摘要、作者、日期与链接。AI HOT API 只能补充，不替代论文来源。

### 具身智能

只从 X.com 搜索页、配置账号和原始帖子获取。不要混用 AI HOT API 或把 HuggingFace Papers 当作该主题主源。

### 软技能与非 AI 主题

组合 YouTube、Reddit、X.com 和即刻中实际启用的平台。优先站内页面和原始内容，不用搜索结果摘要替代正文。

- Reddit：优先相关 subreddit 的近期热门页与原帖，保留社区、得分、评论数和时间。
- X.com：保留原始 status URL、作者、时间与可见互动数据。
- 即刻：只用中文关键词；登录态不足时明确标记。
- YouTube：按下节的 transcript 规则处理。

中文结果不足 3 条时，可使用配置中的英文关键词重试；即刻除外。

## 5. YouTube transcript

对准备写入报告的候选视频：

1. 打开原始视频页，核对标题、频道、发布日期、URL 与可见简介。
2. 尝试从页面 captions、官方 transcript 或宿主提供的转录能力获取字幕。
3. 字幕可用时，记录其来源并生成：
   - 章节或主题分段；
   - 中文核心观点；
   - 少量必要的短引用及中文释义；
   - 与主题的入选理由。
4. 字幕不可用时，不得根据标题补写视频内容。标记 `字幕不可用`，只保留经页面验证的简介级信息。
5. 不复制完整字幕，不输出长段逐字稿；以中文释义和来源链接为主。

## 6. 翻译策略

- 标题可保留原文，中文摘要必须独立成立。
- 人名、公司名、产品名、模型名、库名、技术缩写、代码和 URL 保留原文。
- 自然语言论述以中文意译，首次出现且有稳定译名的术语可写作“中文译名（English term）”。
- 不确定的术语不要强造中文名。
- 短引用可保留原文，但紧邻给出中文释义；遵守来源引用与版权限制。

## 7. 质量筛选与去重

优先保留：

- 一手发布、官方公告、论文原页或原始帖子；
- 当前时间窗口内、与主题直接相关的内容；
- 有可核验事实、数据、经验或明确观点的条目；
- 能补充不同视角而非重复同一新闻的条目。

排除：

- 只有标题、没有可核验正文或原始链接的条目；
- 软文、SEO 聚合页、无来源转述；
- 同一 canonical URL 或同一事件的低信息重复项；
- 与主题关键词同名但语义无关的噪音。

## 8. 增量写入

每个板块完成后立即写入：

```markdown
## <主题>

### <标题>

- 来源：<平台 / 作者 / 时间>
- 链接：<canonical URL>
- 入选理由：<中文>
- 摘要：<中文完整论述，不用省略号掩盖未完成>
- 备注：<仅记录会影响可信度的限制；无则省略>

<!-- section:theme_<ID>_done -->
```

摘要应覆盖被选中的核心信息，但不得复制整篇文章、完整帖子集合或完整 transcript。

## 9. 账号追踪

对 `关注的 X 账号` 中的每个账号：

1. 打开账号主页或可访问的原始帖子列表。
2. 仅保留当前时间窗口内且与用户主题相关的内容。
3. 写入作者、时间、互动指标、完整 status URL 与中文摘要。
4. 账号不可访问时记录一次来源限制，不生成猜测内容。

## 10. 合并与交付

1. 按 `user_config.md` 的主题行顺序合并板块，账号追踪最后。
2. 复核 URL、日期、字幕状态、来源限制和跨板块去重。
3. 移除所有内部 completion markers 与执行日志。
4. 用 `humanizer` 润色最终中文稿，不改变事实、数字、专有名词和 URL。
5. 写入目标路径。
6. Obsidian 启动、博客复制、commit 或 push 必须符合 `output_config.md`，且需要当前用户请求明确授权。
