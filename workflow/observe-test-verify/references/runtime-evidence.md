# 运行证据与测量

用于性能、时序、视觉故障，以及存在多个运行产物副本的定位任务。

## 先确认样本覆盖了目标工作

- 记录采样进程、时间窗口及当时操作。用播放进度、完成帧数、请求或工作事件确认窗口内确有目标工作；弹窗、暂停和空闲样本单独标明。
- 调用栈可提示热点，短样本和少量快照需与计时/日志交叉核对。没有采到某条栈不足以排除该原因，命中次数也不直接等于精确耗时比例。
- 观察不到关键状态时，补充最小诊断或改变采样时机，再进行原因判断。

## 让前后指标可比较

- 使用相同输入、尺寸、功能开关、画质和设备条件。若改变分辨率、算法工作量或缓存条件，把它作为实验变量和结果取舍记录。
- 区分首次初始化、稳定运行和重入/seek；连续测量窗口标明开始、结束和工作量，暂停及跳转窗口不计入稳定吞吐。
- 用完成工作量除以活动耗时计算吞吐。渲染回调次数、提交帧数和最终展示帧率是不同指标，标明测量边界；可用时用实际预览/展示指标交叉核对。
- 根据波动选择足够窗口，记录异常和已知测量开销，不由一张截图推导持续帧率，也不将平均值视为无长帧。

## 将证据绑定实际产物

核对需要的层次：源文件 → 构建/复制的产物 → 当前进程实际加载的产物 → 用户看到的输出。对不明确的环节补路径、版本、哈希或 loaded-image 信息；无需为已清楚的单一入口反复取证。

分别报告这些证据：单测覆盖逻辑或契约；构建检验编译链接；当前进程与日志证明运行路径；实际交互和最终输出证明指定场景。渲染回调返回、资源非空或日志无异常不足以单独证明画面正确。

性能最终结论注明输入、尺寸、配置、测量范围及剩余波动；其他平台、导出或长时间压力场景按实际覆盖情况报告。
